# Q1 Baseline 0 — 逐设施最优机型单目的地往返

## 1. 目的

本基线用于给后续 Q1 多设施联合运输算法提供可复算的对照值。它保留机型选择和 `LAND` 机场分配这两个低成本优化，但禁止一个架次同时服务多个目标设施。

## 2. 基线定义

对每个目标设施 `Fxxx` 独立处理：

1. 同一目标设施的全部人员统一选择一种机型 `T1/T2/T3`；
2. 固定起点 `A01/A02/A03` 的人员不能改变机场；
3. `LAND` 人员可在三个机场之间整数分配；
4. 每个机场按该机型座位数拆分为若干架次；
5. 每个乘客承运架次只服务这一个目标设施；
6. 若燃油约束要求绕行，可在题目指定的 8 个可加油设施进行技术性停靠并加满油，但这些技术停靠不承运其他目标设施人员；
7. 海上实际着陆总次数仍不得超过 5 次；
8. 人员始终由同一架次运送，不换乘。

## 3. 为什么允许技术加油停靠

严格限制为 `机场 -> 目标设施 -> 原机场` 会导致官方 Q1 数据中一部分固定机场需求无可行机型：目标设施本身不是加油点，且往返累计航程超过安全余油允许范围。因此，一个完整 baseline 必须允许必要的加油绕行，否则无法覆盖全部 1600 人。

这不会改变 baseline 的核心限制：**一个架次只服务一个人员目的地**。加油设施仅作为技术停靠点。

## 4. 单机场—设施—机型路线

对机场 `a`、目标设施 `f`、机型 `m`，求满足燃油和最多 5 次海上着陆约束的最短闭环路线：

`a -> [0..若干可加油设施] -> f -> [0..若干可加油设施] -> a`

技术停靠仅允许使用指定加油设施，并一律执行加油；目标设施若本身可加油，可选择是否加油。

路线比较采用词典序：

1. 架次总使用时间最小；
2. 乘客从机场到目标设施的在途时间最小；
3. 总航程最短；
4. 停靠数/路径用于确定性 tie-break。

## 5. LAND 分配

固定某设施 `f` 和机型 `m`。令 `n_a` 为固定从机场 `a` 出发的人数，`L` 为 `LAND` 人数，`x_a` 为分给机场 `a` 的 `LAND` 人数：

`x_A01 + x_A02 + x_A03 = L`，且 `x_a` 为非负整数。

若机型座位数为 `C_m`，则机场 `a` 所需架次数为：

`k_a = ceil((n_a + x_a) / C_m)`。

枚举所有三机场整数分配，选择词典序最优方案：

1. 总飞机使用时间；
2. 人员总在途时间；
3. 总燃油消耗；
4. 总架次数；
5. 确定性分配 tie-break。

由于每个设施的 `LAND` 人数只有几十量级、机场只有 3 个，直接穷举非常轻量。

## 6. 机型选择

分别计算该设施使用 `T1/T2/T3` 的最优 LAND 分配结果，再按同一词典序选择最优机型。因此同一设施只用一种机型，不同设施可以选不同机型。

## 7. 输出与验证

执行：

```bash
python experiments/run_q1_baseline.py --output-dir outputs/q1/baseline
```

会生成：

- `q1-routes.csv`
- `q1-assignments.csv`
- `metrics.json`
- `validation.json`
- `facility_decisions.csv`

流程必须同时通过：

1. Solver-side Fast Checker；
2. Solver-side Evaluator；
3. 官方 CSV Exporter；
4. 独立 Reference Validator 重新读 CSV；
5. 两套指标逐项一致性检查。

只有 Reference Validator `PASS` 的结果才视为有效 baseline。
